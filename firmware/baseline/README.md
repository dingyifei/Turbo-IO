# Baseline: immutable inputs older firmware trees used to provide

This folder replaces the old per-release folder copies (`strix-1.0.5.5-tmg2` … `-tmg7`). They stay in git history and behind the annotated `fw/tmgN` tags. Only files that code in this tree actually reads are copied here, byte for byte. The copied files are never edited: the TMG2 and TMG3 inputs and the 1.0.5.5 to 1.0.5.12 table are frozen. The active rebase table (`rebase-1.0.5.12-to-1.0.6.11.json`) is the exception: it is regenerated for a release, with reviewed additions, and committed as a new reviewed file; `git log` on it holds the history.

## The rebase table chain and which table is active

`tools/rebase_apply.py` lists the tables in `TABLES`, oldest first: `rebase-1.0.5.5-to-1.0.5.12.json` (format `turboio-rebase-1`) and `rebase-1.0.5.12-to-1.0.6.11.json` (format `turboio-rebase-2`). The files that exist in this folder must be a prefix of that list, with no gap. **The active table is the last `TABLES` entry whose file exists here.** Existence decides, so nothing may write a table into this folder by accident: both modes of `tools/rebase_derive.py` refuse an `--out` or `--report` path inside the repository. A table becomes active only by a deliberate, reviewed copy of a generated file in its own commit.

Both files exist since `tmg12(7)`, so the active table is `rebase-1.0.5.12-to-1.0.6.11.json` and the tree is on stock 1.0.6.11. That started as an emulator-only line in TMG12; 1.0.6.11 has been a phone release base since the TMG12 release build, and `fw/tmg17` is the newest release tag on it. `STOCK_BASES` in `build.py` is the endpoints of `TABLES` (all three bases, 1.0.5.5, 1.0.5.12 and 1.0.6.11). The 1.0.5.5 to 1.0.5.12 table stays frozen (its two hashes are in the file list above): it is never regenerated or edited, and the `fw-reproduce` stage of the firmware-only gate rebuilds the newest released tag with that tag's own copy of it. The 1.0.5.12 to 1.0.6.11 table is frozen in the same way from its commit on: a changed row means a newly generated, reviewed file with its own row above.

What the move to 1.0.6.11 left by hand in `build-inputs.json` at `tmg12(7)`, and what that means:

- The output pins (`moduleBytes`, `moduleSHA256`, `APBytes`, `APSHA256`, `archive.bytes/sha256/md5`) were left `null`; every repin since has filled them, and today each one is set. The edits' `after` values were not touched then and still held the TMG11 build's bytes: each `bw`/`bl` encodes a branch from the old site to the old module address, and the allocation edit's `after` is 6 bytes against a new 8-byte `before`. Both fail closed (`pin()` raises on a mismatch, and the build asserts equal `before` and `after` lengths). The first `build.py --repin` writes every output pin and every branch edit's `after`; the raw carousel edit's `after` is a separate, reviewed decision (the `trampolines.S` guard).
- Going back to 1.0.5.12 is not one command. `rebase_apply.py --write --to 1.0.5.12` restores every address, `before`, `pad`, `link.ld` and source value exactly (a round trip back to 1.0.6.11 is byte-identical), but it keeps `stockZIPProvenance`, it drops `stockManifestSHA256`, and the output pins go stale until a repin. Until those are removed or restored and the tree is repinned by hand, `tests/stock_base_test.py` refuses that tree (`stockZIPProvenance present on a official base`).

## Why `kept/` is a copy and not `git show fw/tmg2:…`

`tools/check_kept.py OLD NEW` proves that every `#include` and every called identifier of seven TMG2 files survives in the current tree, except the explicitly removed module symbols. Its input is a directory tree whose `src/` holds the seven TMG2 originals, and `baseline/kept/` is exactly that tree (96 KB). A copy keeps the gate meaning identical (same bytes, same comparison, same exit codes) and works in a shallow clone, in a worktree without tags, and offline. Reading `fw/tmg2` through `git show` would make the test depend on tags being fetched. The tags remain the authority: for every file above, `git rev-parse HEAD:firmware/baseline/<file>` must equal `git rev-parse fw/tmg2:<source path>` (`fw/tmg3:<source path>` for `tmg3-build-inputs.json`), where the source path is the one in the Provenance column (`kept/src/<x>` comes from `firmware-research/strix-1.0.5.5-tmg2/src/<x>`). Verified when this folder was created, and the proposed linecheck repeats the comparison on every run, so an edit to this folder fails H2.
